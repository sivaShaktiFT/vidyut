# Source implementation audit

Audited: 2026-08-11  
Package: `@vidyut-hora/panchanga`  
Scope: the five URLs in [`sources.md`](sources.md)

## Current assessment

The calculation coverage is broad: the package implements the deployed Panchanga limb/rise-set paths, source observances, local-time ephemeris annotations, source-specific natal Raman calculations, vargas, karakas, and Vimshottari helpers. The release-significant runtime and API-contract findings below have been remediated. Independent rendered-page numerical parity remains unverified.

The only open verification issue is the absence of independent source-page golden data. This package is explicitly scoped as a headless core rather than a full source-page replacement; excluded display/catalogue features are documented as non-goals in the README.

## Method

- Re-read the five public source pages and the shared `panchanga-today-widget.js?v=20260728-newage1` loaded by [Monthly Panchanga](https://www.astrologicalmagazine.com/monthly-panchanga.html) and [Daily Panchanga](https://www.astrologicalmagazine.com/panchanga.html).
- Cross-checked the current code against [Vedic Ephemeris](https://www.astrologicalmagazine.com/ephemeris.html), [Default Horoscopes](https://www.astrologicalmagazine.com/horoscope_embed_project/default_charts.html), and [Atmakaraka Calculator](https://www.astrologicalmagazine.com/horoscope_embed_project/atmakaraka.html).
- Reviewed `src/index.ts`, the observance catalogue, README, and all ten tests.
- Ran `npm test`, `npm run typecheck`, `npm run build`, and `npm run test:browser-entry` successfully. Regular tests load the packaged WASM through the Node entry point with `offline: true`; they make no network request.

Status: **match in code** means the same inspected source rule is represented; it is not a numerical comparison with values obtained from the remote rendered page.

## Resolved since the previous audit

- Default Node initialization now succeeds.
- IANA conversion preserves seconds.
- Lunar range uses the source's 06:00 exit boundary.
- Ketu follows the ephemeris source convention in ephemeris APIs.
- Observances, source metadata, locale dictionaries, transition bounds, and a package licence are now present.
- Node support is isolated to `@vidyut-hora/panchanga/node`; it reads the packaged WASM without replacing global `fetch`, and concurrent initialization is tested.
- Ephemeris data downloads are opt-in through `ephemerisUrl`/`ephemerisFiles`; the default and regular test path are offline.
- Locations must supply exactly one timezone representation. IANA offsets are resolved for the requested civil date and passed into source fallbacks.
- `Panchanga.events` reports `altitude`, `swiss`, or `approximation` provenance for every rise/set value.
- Public civil/birth/date/hour entry points now reject invalid or overflow values; UTC conversion has an explicit timezone formatting helper.
- The browser entry has no Node specifier, enforced by `npm run test:browser-entry`.
- Remaining source-page presentation/catalogue gaps are explicit README non-goals.
